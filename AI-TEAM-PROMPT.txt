EVERY CODE CHECKPOINT / GITHUB PUSH / SANDBOX DEPLOY REQUEST

3. Successfully git fetch origin. Compare commit ancestry, not clock/file dates or the last-pull time. If git merge-base --is-ancestor origin/main HEAD shows main is not included, normally merge origin/main into the candidate. Preserve teammate commits and behavior. 6. Fetch again just before publication. If main advanced, merge it, review and rerun affected validation. Normally push the validated combined checkpoint to the explicit main target:
   git push origin HEAD:refs/heads/main
If a concurrent update rejects the push, repeat fetch -> merge -> validate -> normal push. Never --force, --force-with-lease, + refspec, --mirror, --all or destructive shared-history rewriting. Fix/report actual auth/network/permission failures rather than treating every rejection as a race.
7. Honor existing branch protections. If a PR/check/review is required, publish the checkpoint branch and open/update the PR, refreshing integration as needed. Do not disable/bypass rules. A pending PR or WIP branch is not consolidated main. After acceptance, fetch and verify the published SHA is an ancestor of origin/main. Record the latest observed main SHA. DEPLOYMENT RACE AND SETUP DEPENDENCY
Git merges and a last-minute fetch do not prevent an older slow PAC upload from finishing after a newer one and replacing it. Everyone must use the same serialized publisher; a laptop-local note/lock is not cross-machine enforcement.
Recommended: one GitHub Actions main deployment workflow, one fixed app-wide concurrency group such as compass-cms-sandbox-deploy, cancel-in-progress: false, and fetch/select/recheck current main after obtaining concurrency. Coalesce queued requests to deploy the latest combined main. An approved shared publisher service with a real distributed lock is also acceptable.
Until this is configured and verified, do not issue uncoordinated direct laptop PAC pushes. Report the deployment-queue setup dependency. Do not create credentials, edit GitHub settings or install deployment workflows merely by adopting this policy. The policy files alone are not functioning automation.
